# 004: Better Auth on the database

Status: done

Connect Better Auth to Turso through the Drizzle adapter, with the organization
plugin and teams.

## Acceptance criteria

- [x] Drizzle adapter uses the hand-written schema from task 003
- [x] Organization plugin with teams enabled, no default team
- [x] Better Auth generates UUIDv7 ids
- [x] `team_member.role`: Better Auth 1.7 has no additional fields on team members, so
      it is an app-managed column (recorded in `docs/architecture.md`)
- [x] Organization deletion disabled in the plugin (users and orgs are never hard-deleted)
- [x] Account deletion stays disabled (Better Auth default); anonymization is a later task
- [x] Sign up, create organization, create team, invite into a team, accept, and
      organization deletion refused: checked over HTTP against the local database
- [x] Email + password sign-in enabled only when `NODE_ENV` is `development`; the MVP
      sends no email (email delivery is task 016)
- [x] Google sign-in enabled when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are both
      set; setting only one fails at startup
- [x] Type errors in `src/routes/api/auth/$.ts` resolved (route tree regenerated by Vite;
      the `tsr`-based `generate-routes` script, which dropped the Start types, removed)
